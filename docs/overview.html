Trace archival on PostgreSQL

This benchmark measures how long PostgreSQL takes to find the next batch of traces for MLflow to archive. It checks that queries return the oldest eligible traces first and use the trace ID to break timestamp ties.

Read a saved report

Use Git and Python 3.10 or later to read the saved million-trace report. The script uses the Python standard library.

Shell 
git clone https://github.com/kenchengkc/mlflow-trace-archive-bench.git
cd mlflow-trace-archive-bench
python3 summarize.py results/strategy-study/million-late.json.gz --with-planning

All three queries returned 100 traces. The timing columns give the median planning and execution time in milliseconds for each query.

Run a local benchmark

On macOS or Linux, install the PostgreSQL tools and put initdb, pg_ctl, and psql on your PATH. Run this command from the cloned repository as a non-root user.

Shell 
python3 matched_queues.py --rows 1000 --batch-size 3 --samples 2

The script creates two 1,000-trace queues in a temporary database. It archives the oldest 95% of eligible traces in one queue and scatters the same number across the other. It checks that all three queries return the expected trace IDs in order, then prints their timings.

Query timings

In the million-trace study, the global query took 1.24 ms to select 100 traces from a fresh queue across eight experiments. After the benchmark archived the oldest 95% of eligible traces, the same query took 1,315.50 ms. The bounded probe took 284.59 ms on that queue. It checked the oldest 200 matching trace headers, found none eligible, then searched the full queue.

Study guides

SQL query strategies
Compare the global query, per-experiment merge, and bounded probe on two queues with the same archive depth but different layouts.
MLflow’s candidate finder
Compare raw SQL with MLflow 3.18.0’s tracking store. Check how it merges tied timestamps when 1,001 experiments require two queries.
Concurrent trace ingestion
Measure how quickly MLflow selects traces while it writes new ones. Break down the cost of adding 64 KiB to each span.
