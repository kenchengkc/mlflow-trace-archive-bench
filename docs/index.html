MLflow Trace Archival Benchmark

Compare how PostgreSQL finds the oldest eligible traces for MLflow to archive, and verify that each query selects the same batch in the same order.

Quick start

Inspect the saved million-trace result with Git and Python 3.10 or newer. The report reader uses only the standard library.

git clone https://github.com/kenchengkc/mlflow-trace-archive-bench.git
cd mlflow-trace-archive-bench
python3 summarize.py results/strategy-study/million-late.json.gz --with-planning

How archive depth changes selection time

On one million synthetic traces, the global SQL query selected 100 traces in 1.24 ms on a fresh queue. After the oldest 95% of eligible traces were archived, it took 1,315.50 ms. A query that checked a short prefix before falling back to a full search took 284.59 ms on that late batch.
